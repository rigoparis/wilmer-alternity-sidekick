## 3. UI Architecture & Functional Map (`scripts/main.gd`)
Because `main.gd` is ~4600 lines long, this index highlights where key features, initialization routines, rendering passes, and modal handlers reside.

### Layout Initialization & Resizing
- **`_ready()` / `_build_shell()` (Lines 95 - 250)**: Preloads rules, checks for autoloading characters from `user://last_character.txt`, builds base background panels, tabs, headers, and pre-renders modal overlays.
- **`_apply_responsive_layout()` (Lines 264 - 294)**: Computes viewport dimensions to scale UI elements (Desktop/Tablet vs. Compact Mobile) and calls `_resize_modal_panel` to scale dialog dimensions dynamically.
- **`_notification()` (Lines 141 - 150)**: Detects window resize events and triggers dynamic layout adjustments.

### View State & Tab Routing
- **`_set_tab()` / `_clear_tab_cache()` (Lines 1005 - 1027)**: Routing system for tab switches. Tracks previous scroll positions, switches node visibility, and flags rendering caches.
- **`_render()` (Lines 1033 - 1130)**: Central controller for drawing. Validates active tab container cache, updates character basics panel, conditionally clears the selection overlay, and restores the scroll offset deferred.

## 4. UI Architecture Patterns

### Tab Caching & Lazy Rendering
- **The Lifecycle**: Instead of tearing down the DOM on every screen transition using `queue_free()`, the main UI uses a tab container cache (`_tab_containers` dictionary).
- **Lazy Instantiation**: Tab containers are instantiated and added to the scene tree only when they are first visited.
- **Visibility Toggling**: Changing tabs toggles `visible = true/false` on cached containers.
- **Dirty Flags**: When character data changes, the cache is not destroyed immediately. Instead, a `_tab_dirty` flag is set to `true` for all tabs. The active tab is immediately rebuilt, while inactive tabs are deferred and only rebuilt when the user clicks on them.

### Scroll Position Management
- **Scroll Position Persistence**: Because ScrollContainer positions can get reset or share layout sizes, `main.gd` tracks independent scroll offsets in `_tab_scroll_positions` during tab transition.
- **Restoration**: Scroll positions are restored dynamically via `_restore_scroll_position.call_deferred()` at the end of the rendering phase to ensure layout passes have completed.

## 5. Rules Engine Architecture (`scripts/alternity_rules.gd`)
The core rules logic is decoupled into sub-modules instead of a single giant monolithic class.

### Method & Functional Index
Below is the map of where primary methods are defined in `alternity_rules.gd`:
- **Core Initialization & Data Loading (Lines 15 - 180)**:
  - `clear_cache()`: Clears local evaluation caches.
  - `load_core_data(path)`: Dispatches JSON load requests.
  - `_load_equipment_catalog(path)`: Indexes armor, weapons, and accessories.
  - `_load_achievement_catalog(path)`: Parses milestones and level-up charts.
  - `_load_mutation_catalog(path)`: Loads mutant disadvantages and benefits.
  - `_load_psionics_catalog(path)`: Loads talent arrays.
- **Character Templates & Setters (Lines 181 - 299)**:
  - `default_character()`: Generates the blank JSON schema.
  - `ensure_character_shape()`: Backfills missing keys or list indices.
- **Catalog Lookup Getters (Lines 300 - 397)**:
  - `get_species_by_id()`, `get_profession_by_id()`, `get_skill_by_id()`
  - `get_equipment_item_by_id()`, `get_achievement_by_id()`, `get_mutation_advantage_by_id()`, `get_mutation_drawback_by_id()`
  - `get_perk_by_id()`, `get_flaw_by_id()`
- **Ability & Feat Score Translators (Lines 398 - 498)**:
  - `effective_abilities()`: Combines base scores + achievement updates.
  - `untrained_score()`: Calculates default untrained roll check targets.
  - `resistance_modifier()`: Translates ability scores to step penalties/modifiers.
- **Derived Mechanics (Lines 499 - 611)**:
  - `action_check()`: Computes the base check value and step die.
  - `durability()`: Computes Stun, Wound, Mortal, and Fatigue thresholds.
  - `movement()`: Walk, Run, Easy Swim, Swim rates.
  - `actions_per_round()`: Number of active phases.
- **Skill Points Accounting (Lines 612 - 720)**:
  - `skill_budget()`: Re-calculates total spent/remaining points.
  - `max_broad_skills()`: Total broad skills allowed.
- **Character Audit Summary Compiler (Lines 721+)**:
  - `summary(character)`: Compiles all values, validates attributes, skills, armor ratings, and purchases, and caches the results based on `character.hash()`.

### Sub-Module Layout
Avoid delegating calls directly to `AlternityRules`. Instead, access the decoupled sub-modules directly:
- **Mutations**: `rules.mutations` (e.g. `rules.mutations.mutations_enabled(character)`)
- **Achievements**: `rules.achievements` (e.g. `rules.achievements.add_achievement_purchase(character, ...)`)
- **Equipment**: `rules.equipment`
- **Skills**: `rules.skills`
- **Professions**: `rules.professions`

### Performance & Memoization
- **Character Summary Caching**: The heavy rules compiler `summary(character)` uses a hash-based cache (`_cached_summary` dictionary).
- **Hash Checks**: The key is the stable `character.hash()`. Recalculation is skipped unless the character's core properties change.
- **Cache Clearing**: Call `clear_cache()` explicitly when loading or switching to a new character.

### Type Robustness
- Use `rules._as_int(value)` for converting dynamic config parameters. It safely handles `null`, `float`, and `String` inputs to prevent runtime GDScript exceptions.

## 6. Verification & Testing
Before committing or pushing any code changes, verify that the headless test suite passes.

### Smoke Tests
Run tests headlessly from the root directory using the Godot binary:
```powershell
# Core rules validations
godot --headless --path . -s tools/debug_validation.gd

# Mutation rules logic
godot --headless --path . -s tools/smoke_mutations.gd

# Mutation UI renderer test
godot --headless --path . -s tools/smoke_mutation_ui.gd

# Achievement points calculation
godot --headless --path . -s tools/smoke_achievements.gd

# Profession ability boosts
godot --headless --path . -s tools/smoke_profession_abilities.gd

# Equipment database catalog loader
godot --headless --path . -s tools/smoke_equipment_catalog.gd
```

> [!WARNING]
> **GDScript Type Inference Constraint**: When assigning variables from chained dynamic sub-module calls, GDScript cannot statically infer the type.
> Avoid using static type inference assignments like `var result := rules.mutations.add_mutation(...)` as this causes compilation failures.
> Use explicit typing `var result: Dictionary = ...` or standard assignments `var result = ...`.
